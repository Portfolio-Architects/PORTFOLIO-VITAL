# 레이 달리오 원칙 기반 의사결정 · 진단 · 시스템 진화 스킬 (vital-principles-os)

## ▣ 1. 개요 및 목적 함수

### ▢ 1. 시스템 목적 함수 및 SSOT 경계
- 본 스킬은 **$\mathcal{J}_{\text{Ontology}}$ (암묵지·원칙 자산화)** 및 전 도메인 의사결정·장애 진단의 메타 운영체제(`Rule T`)를 수행함.
- **적용 기조 (`AIA Labs` 보조 엔진형):** AI를 인간 감시·자동 결재 엔진(`PriOS` 실패 모델)으로 쓰지 않고, 인과 검증·확률 비교·원칙 매칭·재발방지 가드레일 설계의 보조 엔진으로 한정함.
- **연계 SSOT:** `AGENTS.md`, `data/WORKING_MEMORY.json` (`category: 'issue_log'`, `issueMeta`), `src/lib/working-memory-parser.ts`, `src/lib/schemas.ts`, `data/TASKS.json`, `data/SCHEDULES.json`, `data/BUDGET_SIMULATIONS.json`, `data/ADMIN_DOC_INDEX.json`, `PORTFOLIO VITAL - Engineering Report.md`.

### ▢ 2. 타 스킬 연계 핸드오프
- **예산·계약 (`vital-budget-audit`):** 대안별 $EV$·`Risk of Ruin = 0` 검토 후 3중 총액 일치·`405-01` 이중 실행 검산을 연계함.
- **문서·방침서 (`vital-hwpx-docgen`):** 결정된 최종안의 인과 근거·1~3차 파급효과·추진과제(`RP`)를 3단 방침서 본문에 반영함.
- **거버넌스 (`vital-governance-ops`):** `Issue Log`에서 도출된 기계 차원 개선안을 마일스톤 기록(`scripts/sync-rules.js`)·일정·작업기억으로 환류함.

## ▣ 4. 단계별 실행 런북

### ▢ Phase 1. 5단계 프로세스 분리 및 근접·근본원인 품사 진단
- 모든 복합 과업·장애 대응 시 아래 5단계를 순차 분리 출력하며, `2단계(문제)`에서 `4단계(설계)`로 직행하는 단축을 차단함.
- **계층 분리(`선 위` vs. `선 아래`):** 거시 목표·원칙(`선 위`)과 세부 작업·수치(`선 아래`)를 혼합하지 않고 구분 표기함.

| 단계 | 필수 산출 항목 | 누락·혼합 차단 게이트 |
|:---:|:---|:---|
| **1. 목표** | 정량 목표 1~3개 · 우선순위(포기 항목 명시) | 모든 욕망 동시 나열 금지 |
| **2. 문제** | 목표 대비 괴리(팩트·수치) · 위험등급 | 완곡어·책임 회피성 익명(`우리/그들`) 금지 |
| **3. 진단** | 근접원인(동사·1회성 행위) → 근본원인(형용사·지속적 구조/속성) · 사건(`Case`)/기계(`Machine`) 분리 | 동사 단계에서 진단 종료 금지 |
| **4. 설계** | 재발방지 가드레일(훈련·체크리스트·자동화·우회로) · `RP`(직제명) · 마감일 | 일회성 주의 촉구만으로 설계 대체 금지 |
| **5. 실행** | 실행 단위 분해 · 완료 검증 기준(`Done`) · `Double-do` 대상 지정 | 검증 기준 없는 실행 착수 금지 |

### ▢ Phase 2. 확률적 의사결정($EV$), `Risk of Ruin = 0` 및 2·3차 결과 평가
- 중대 정책·예산·계약·아키텍처 선택 시 선 학습(법령·아카이브 RAG) 후 아래 기댓값 틀로 대안을 비교함:
  $$EV = (P_{\text{성공}} \times \text{성공 보상}) - (P_{\text{실패}} \times \text{실패 비용})$$
- **파산위험(`Risk of Ruin`) 0 게이트:** $EV$ 수치와 무관하게 ① 법령·조례 위반, ② 예산 3중 총액 불일치·초과 집행, ③ PIPA 개인정보 평문 유출, ④ `D:\Desktop`·아카이브 원본 파괴 가능성이 `> 0`인 대안은 즉시 탈락 처리함.
- **2·3차 파급효과 및 80/20 집중:** 1차 단기 편의보다 2차(차년도 예산·감사·유지보수)·3차(조직 신뢰·인수인계) 결과를 우선 평가하며, 핵심 5~10개 동인에 집중해 불완전주의자 태도로 지연 비용을 통제함.

### ▢ Phase 3. 신뢰도 가중 삼각측량 및 토론·결정 권리 분리
- 근거·의견 충돌 시 등가중치 나열을 지양하고 아래 3등급 신뢰도 기준으로 가중 평가함:
  - **Tier 1 (최상위 신뢰도):** 현행 법령·조례·공식 지침 또는 당해/과거 아카이브 3회 이상 검증 실적 + 인과 논리 충족.
  - **Tier 2 (중간 신뢰도):** 단일 선례 또는 인과 논리 중 한 축만 충족(교차 검증 필요).
  - **Tier 3 (저신뢰 추정):** 실적·인과 근거 부재 추정치(의사결정 가중치 배제).
- **권리 분리:** 다각적 반론 검토(토론 권리)와 최종 결정 주체(`RP`, 결정 권리)를 구분 표기하며, 결정 확정 후에는 이행 계획과 완료 기준에 집중함.

### ▢ Phase 4. 고위험 업무 이중 실행(`Double-do`) 및 `Issue Log`·`Living Manual` 환류
- **이중 실행(`Double-do`) 대상:** 결재용 예산 산출표, `405-01` 추정가격·계약절차 판정, 법정 기한·의회 답변 수치, 운영 SSOT(`data/*.json`) 마이그레이션은 단순 재검토(`Double-check`) 대신 독립 경로 2개(수기·원본 산식 vs. 스크립트·하네스 재연산)로 결과를 교차 대조함.
- **`Issue Log` 구조화 환류 (사건 → 기계 진화):** 반복 실수·장애·감사 지적 발생 시 `data/WORKING_MEMORY.json`에 `category: 'issue_log'` 및 `issueMeta`(`severity`, `responsibleParty`, `proximateCause`, `rootCause`, `machineFix`, `doubleDoRequired`) 형식으로 기록하고, 구조적 교훈은 `PORTFOLIO VITAL - Engineering Report.md` 및 해당 `SKILL.md`·하네스 테스트로 승격 반영함.
- **표준 1줄 입력 문법 (`WorkingMemoryPage` 자동 파싱):** `[이슈로그] RP:<직제명> | 근접:<동사 행위> | 근본:<형용사·구조 속성> | 개선:<재발방지 가드레일> | 위험:<치명/상/중/하>`

## ▣ 5. 금지 패턴 및 안티패턴 체크리스트

| 구분 | 안티패턴 (Strictly Prohibited) | 정상 표준 대응책 (Compliant Standard) |
|:---:|:---|:---|
| **AP-P1** | 문제 인지 직후 진단 없이 해결책 설계로 점프 | `목표 → 문제 → 진단(동사→형용사) → 설계 → 실행` 분리 준수 |
| **AP-P2** | 근접원인("확인을 누락함")에서 분석 중단 | 근본원인("검증 자동화 부재·단일 경로 의존")까지 추적 후 가드레일 설계 |
| **AP-P3** | `Risk of Ruin > 0` 대안을 높은 단기 편의로 채택 | 법령·예산·PIPA·원본파괴 파국 확률 `0` 미만족 대안 즉시 탈락 |
| **AP-P4** | 익명 주어("우리", "관련 부서")로 책임 모호화 | 직제명 기반 `RP`(PIPA 준수)·마감일·검증 기준 명시 |
| **AP-P5** | 고위험 수치에 눈대중 재검토(`Double-check`)만 적용 | 독립 산식·스크립트 기반 이중 실행(`Double-do`) 대조 강제 |
| **AP-P6** | `Dot Collector`·`Pain Button`·`Baseball Cards`형 감시·낙인 도입 | 사람 평점화·감정 수집 배제, 시스템(`Machine`)·프로세스 개선에 한정 |
| **AP-P7** | 깊은 인과 이해 없이 AI 출력을 무검증 결재·자동 집행 | `AIA Labs`형 보조 원칙 준수, 원천 법령·아카이브·하네스 교차 확인 |
